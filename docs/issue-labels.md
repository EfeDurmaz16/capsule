# Issue Labels

The label set below is the one that actually exists on the GitHub repository. Apply labels from here; do not invent new ones without adding them on GitHub first.

## Default Labels

`bug`, `documentation`, `duplicate`, `enhancement`, `good first issue`, `help wanted`, `invalid`, `question`, and `wontfix` are the standard GitHub defaults and keep their usual meaning.

## Area Labels

| Label            | Use for                                                             |
| ---------------- | ------------------------------------------------------------------- |
| `area:core`      | `@capsule-sdk/core`, capability model, policy, receipts, contracts. |
| `area:providers` | Provider adapter packages and provider-specific behavior.           |
| `area:cli`       | `@capsule-sdk/cli`, command output, and operator UX.                |
| `area:docs`      | README, public docs, ADRs, examples, and quickstarts.               |

## Provider Labels

One per adapter: `provider:docker`, `provider:e2b`, `provider:daytona`, `provider:modal`, `provider:cloud-run`, `provider:cloudflare`, `provider:vercel`, `provider:neon`, `provider:kubernetes`, `provider:lambda`, `provider:ecs`, `provider:ec2`, `provider:fly`, `provider:azure`.

## Other Labels

| Label                | Use for                                                          |
| -------------------- | ---------------------------------------------------------------- |
| `type:security`      | Policy bypasses, secret handling, receipt trust, IAM boundaries. |
| `needs-verification` | Work is not done until verification evidence is posted.          |
