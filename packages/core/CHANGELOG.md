# @capsule-sdk/core

## 0.2.0

### Minor Changes

- e1f022d: Add the artifact evidence surface. `verifyArtifactHash(artifact, content)` recomputes a file's sha256 and reports a structured result, treating a missing claimed hash as unverifiable rather than trusted. `createArtifactManifest(artifacts)` produces a versioned `capsule.artifact.manifest.v1` manifest whose sha256 digest is taken over the canonical (key-sorted, undefined-dropped) payload, with `verifyArtifactManifest` for tamper detection; the digest is stable under key order and covers `createdAt` and every entry. `collectFileArtifacts(dir, options?)` walks a directory with `node:fs`, hashes each regular file into an `Artifact`, never follows symlinks, emits deterministic sorted output, and bounds the walk with `maxFiles` (default 1000) and `maxBytes` (default 64 MiB), returning explicit truncation info. `ExecSpec` gains an optional `artifactPaths?: string[]`. The Docker adapter now honors it: `sandbox.exec` copies the requested container paths out with `docker cp` and hashes them via the collector, returning them on `ExecResult.artifacts` and the receipt's `artifactHashes`. `job.run` still returns no artifacts because `docker run --rm` removes the container before collection; this stays documented in the capability map and docs/artifacts.md.
- 72d873a: Concurrent sandbox sub-operations no longer silently drop receipts: adapter emission is tracked per operation instead of being inferred from the shared receipts array length. The default redaction profile now covers everything the receipt verifier flags (AWS access key ids, postgres connection URLs, password= fragments) from one shared credential pattern, and receipt command, source, and cwd fields are redacted at creation as defense in depth. The CLI preview cleanup file gained its own format identifier, capsule.cli.preview-cleanup-file.v1, while still accepting files written with the previous shared string.
- 6488af5: Add shared lifecycle, capture-bound and approval contracts for adapters.

  - `Machine["status"]` is now `MachineStatus`, which adds the transitional values `starting`, `stopping` and `destroying` that machine lifecycle operations already returned. Exhaustive switches over machine status must handle them.
  - New typed outcomes: `PendingOperationError` (accepted, not yet terminal), `UnknownOutcomeError` (cannot tell whether the provider applied the action, never retry-safe) and `PartialEffectsError`, plus `resourceLocator()` for safe locators and `observeUntilTerminal()` for deadline-bounded observation. `CleanupFailureError` accepts an optional structured `effects` record; `partialEffectsOf()` reads it from either class.
  - New `CaptureBounds` (`maxBytes`, `maxRecords`, `deadlineMs`, `concurrency`, `overflow`) on exec and logs specs, with `truncation` on results, `CaptureBudget`, `resolveCaptureBounds`, `resolveExecOutputBounds`, `readBoundedText`, `mapWithConcurrency` and `defaultCaptureBounds`. Adapters adopt them individually.
  - `ExecSpec.approval` and `sandbox.destroy({ approval })` carry a fresh per-operation grant that replaces the captured create grant for that call and is validated for its own capability and resource. The captured grant remains a validated fallback. The approval is not forwarded to adapters. `CleanupApprovalResolver` is the shared type for fresh cleanup approval.

- a0d12be: Deepen the policy and receipt control-plane surface. `PolicyDecision` now carries a typed `enforcement` mode (`native`, `delegated`, `advisory`, `unsupported`) derived conservatively from adapter-declared support, an ordered evaluation `trace`, and `cost`, `ttl`, and `network` decision objects (including per-host allowlist diagnostics and the adapter network policy support level) when the policy declares them. The `enforcement` mode and these diagnostics travel into the receipt policy section. A new `mergePolicy(base, override)` combines two policies while always failing toward the stricter side, with documented per-field rules. Receipts gain an optional `schemaVersion` stamped as `capsule.receipt.v1`, an optional `parentId` for receipt chaining, and `metadata.sourceResourceId` / `metadata.parentResourceId` for resource lineage. New `redactionFixtureTokens` and `redactionFixtureObject` exports provide fake, clearly-marked credential-shaped fixtures for redaction tests, and the adapter contract fixtures add `logs` and `lifecycle` kinds.
- b14410b: Credential-shaped tokens (Bearer values, provider key prefixes, JWTs) are now redacted from Capsule-observed logs, receipts, and errors on every redaction profile, not only under `redactionProfile: "strict"`; matching is case-insensitive to stay consistent with `verifyReceipt`. The strict profile still adds the broad long-token catch-all. `capsule doctor` now reports Node versions below 22 as unsupported, matching the declared engines floor. The Azure Container Apps adapter reads HTTP status from the provider error classification as a fallback when detecting missing jobs.
- f82ce34: Add crash-safe cleanup. `new Capsule({ owner: { job } })` labels every create with `capsule_operation` (new per create) and `capsule_job`. `capsule.gc.scan({ liveness })` lists labelled resources from an adapter's new optional `residuals.list()` and splits them into residuals (owner `ended` or `exited`) and kept (`live` or `unknown`). `capsule.gc.remove({ liveness, approve })` removes residual sandboxes: each removal needs its own fresh grant scoped to `sandbox.destroy` alone and that resource (a grant that allows any other capability is refused), writes a `sandbox.destroy` receipt, and counts as removed only when a second scan no longer lists it. `JobLeases` keeps per-job leases on disk, proves liveness from them, and `prune`s the leases of finished jobs that left nothing listed; `liveSet({ live, ended })` builds a liveness from sets the caller holds, where an owner in neither set is `unknown` and kept. `consentApprovals` turns a person's confirmation of the listed resources into one such grant each, and `withJobLease` runs work under a lease so a crash leaves it for gc.
- 78f0b9a: Add optional log cursor pagination and log source attribution to the core log surface. `JobLogsSpec`, `ServiceLogsSpec`, `EdgeLogsSpec`, and `PreviewLogsSpec` gain an optional `cursor`, their results gain an optional `nextCursor`, and `LogEntry` gains an optional `source` for instance attribution. Both additions are optional and backward compatible.

  Cloud Run wires the cursor through Cloud Logging `pageToken`/`nextPageToken`. Kubernetes wires it through the pod list `continue` token and tags each combined log line with its source pod name. Docker tags `sandbox.exec` result logs with the container id. Cloudflare edge logs stay `unsupported` with a documented rationale (live tail is WebSocket-only; the bounded telemetry query API is opt-in and its event schema is unversioned). New `docs/log-normalization.md` consolidates the per-provider mapping and states that captured logs are best-effort bounded snapshots, not complete transcripts.

- 9c9340d: Add an optional tracing hook: pass `trace: { tracer }` with any OpenTelemetry API tracer and every operation gets one span with its operation id, job, provider, action, outcome, policy decision and SHA-256 digests of the idempotency key and approval ref; receipts, denials, pending and unknown outcomes are span events. Core takes no dependency, and spans never carry env values, raw approval refs, output, error text, or argv unless asked for on a policy that does not redact logs. A result whose provider status is still in progress (queued, deploying, creating, building, resetting and the like, or running outside machines) is `pending`, and a `failed` or `partial` status is `failed`, with the status itself as `capsule.result.status`.
- 8a5abed: Preview environments derive their overall status from resource statuses via the exported `aggregatePreviewStatus` (any failed resource fails the preview, pending resources keep it creating) instead of a hardcoded ready. `previewUrlRegistry` and the new optional `urlEntries` field on PreviewEnvironment map each URL back to its resource id, type, and provider.
- 467b824: Let a cleanup approval resolver tell same-id resources apart.

  `CleanupApprovalRequest` gains an optional `context` with the resource provider, the adapter name of the Capsule that runs the cleanup, the graph-local `resourceRef`, the cleanup `actionId`, the `previewId` and the provider `scope` (for example the database project). Preview cleanup fills it for every request, so two services named `web` in different namespaces or on different providers no longer produce identical requests. The request `resource` and the approval hint Capsule core evaluates for `service.delete` and `database.branchDelete` now both carry the adapter `provider`, so a grant scoped to one provider matches only that provider's resource. A grant scoped without `provider` matches as before.

- 951af73: Adopt the provider error taxonomy across every adapter. Core adds `classifySdkError`, `asProviderError`, and `callProvider` so SDK-based adapters normalize provider error shapes (status codes, error names/codes) into the shared retryable/rate-limit/auth/validation categories. The docker, kubernetes, lambda, ec2, ecs, e2b, daytona, modal, and mock adapters now attach `cause.providerError` on failures instead of throwing raw errors, so callers get the same typed categories the six HTTP adapters already emitted. Docker classifies conservatively from CLI exit codes and stderr signals. Each adapter contract test now exercises the shared failure-scenario harness with a real scenario, and the Azure Container Apps client gains explicit classification tests.
- 2dc1196: Add `Capsule.sandbox.attach({ id })` and the optional `SandboxAdapter.attach`. Attaching wraps an existing sandbox so exec, file access and destroy on it are governed like operations on a created sandbox: policy, fresh approvals and receipts apply per operation. Attaching itself changes no provider state, evaluates no policy and writes no receipt, and it carries no captured create grant, so destroy needs its own approval where policy requires one. An adapter without `attach` fails with `UnsupportedCapabilityError` before any provider call.

### Patch Changes

- fc02fac: Deleting an already-absent Neon branch or Cloud Run service is now idempotent success instead of a leaked disposition, matching the Azure adapter; core exports the shared `providerErrorStatus` helper. The Lambda adapter throws `AdapterExecutionError` for missing function names instead of a bare `Error`, and `cloudRun()` accepts zero arguments like its siblings.
- fbae6f0: Bounded body readers (`readBoundedText`, the Cloudflare, Fly, Neon and Vercel HTTP clients and the Vercel runtime log reader) no longer call `releaseLock()` on a body they finished, cancelled or saw fail. In Node, `releaseLock()` builds an error whose first use creates a `vm` context, about 1 ms on the first request of a process. The body stays locked, which only matters to code that tried to read a body the client already consumed. Results and caps are unchanged.
- 70cee7f: `collectFileArtifacts` hashes every file of one walk through a single read buffer and treats a short read as the end of the file once the bytes read reach the file's nonzero size, so a small file takes one read again while a file system that returns short reads before the end (FUSE, NFS, SMB) is still hashed whole. Sizes, hashes, budgets and truncation are unchanged.
- 0f6ef03: `collectFileArtifacts` checks each opened file's size against the remaining `maxBytes` budget before reading any content, hashes through a fixed 64 KiB buffer, and stops reading if a file grows past the budget after that check. An oversized file is no longer read into memory just to be skipped. Inventory, hashes and the whole-file-or-skip truncation semantics are unchanged. This is not a guarantee against a hostile tree that is mutated during collection.
- 42953dc: Document that `runAdapterContract` and `runCapsuleAdapterContract` are guard-only checks: they verify declarations, unsupported-capability errors, approval fail-closed behavior and supplied failure scenarios, but do not run a successful lifecycle. The `adapterContractFixtures.lifecycle` note no longer claims the lifecycle is exercised end to end; it states the fixture is descriptive data for adapter tests.
- 45d50ee: Sandbox operations no longer share required receipt-write waits. Under `receiptPersistence: "required"`, each sandbox operation awaits only the receipt writes it emitted, so a slow or failing write for one operation no longer delays or rejects a concurrent sibling. The facade also stops keeping every emitted receipt and completed write promise alive for the lifetime of a sandbox handle; receipt history is now held only by the configured receipt store.
- 1488e6a: `verifyReceipt` now derives its schema verdict from the exported `capsuleReceiptJsonSchema`, so the runtime check agrees with the published schema. Receipts with an unknown `schemaVersion`, wrongly typed optional members (for example a string `resource` or a non-string `command` element), unknown top-level or nested properties, or invalid policy `enforcement`, `trace`, `cost`, `ttl` or `network` entries are now reported as schema-invalid. Receipts that omit `schemaVersion` remain valid. Some schema error messages are worded differently.
- fd7307a: `redactError` now also redacts an `Error.stack` string that was materialized before redaction, on the error and on nested `cause` errors. Previously the stack kept the original first line, so logging a thrown error could print a credential that the redacted `message` no longer showed. The error keeps its class, identity and stack frames, and cyclic `cause` chains no longer recurse forever.
- e65957b: Adapter-side `context.evaluatePolicy()` calls made during a sandbox exec, file or destroy operation now evaluate against that operation's capability path. Previously they had no capability path, so any capability-scoped approval grant, including a fresh per-operation grant, was rejected inside the adapter even though the facade had accepted it.
- cf1ba2a: `mergePolicy` no longer widens a deny-all secrets policy. A `secrets` block that omits `allowed` already denies every env key at evaluation; merging it with a block that lists keys used to keep that list and permit those keys. When both sides declare a `secrets` block, the merge now intersects their effective allowlists, treating an omitted `allowed` as `[]`, so the merged policy accepts only env keys that both sides accept, in either merge order. Evaluation semantics are unchanged.
- aa604d6: License metadata unified to MIT across every package, matching the repository LICENSE and README; each package now ships the LICENSE text in its tarball. The dead `packages/core/src/domains/` re-export barrel was removed (it was never exported or built).
- 9ed60f4: Stop packing declaration files the package's `types` entry never reaches, and declaration maps for core and docker, which pointed at sources the packages do not ship. What a consumer can import is unchanged.
- 2856feb: `@capsule-sdk/core` gains three preset factories and an exported policy validator. `ciJobPreset` wraps `nodeJobPreset` with CI defaults (CI=true env, 15 minute timeout). `dockerLocalAgentPreset` wraps `nodeSandboxPreset` for a locally sandboxed Docker agent with a deny-by-default network. `costLimitedPreviewPreset` wraps `previewEnvironmentPreset` and adds a `policy.cost.maxUsd` spend cap (default $5). `validatePresetAgainstPolicy(preset, policy)` returns structured findings for allowlist, cost, ttl, and timeout issues; the previous private validators now delegate to it.

  `@capsule-sdk/presets` gains `cloudflareNeonPreviewPreset` and `vercelNeonPreviewPreset`, composing the existing edge and Neon presets the same way `flyVercelNeonPreviewPreset` does, and a static `presetCatalog` describing every core and provider preset for discovery.

  `@capsule-sdk/cli` gains `capsule receipt inspect --receipt-file <path> [--id <receiptId>]` (pretty-prints stored receipts without validating them), `capsule preset list` (table or `--json`) and `capsule preset explain <id>` over the catalog, and `capsule preview plan --config-file <path>` (a side-effect-free dry-run report). `capsule doctor` now honors `--provider` when filtering credential diagnostics.

- 575c614: Capsule instances now share one AsyncLocalStorage for operation context instead of creating one each. Each instance still sees only its own innermost operation. On Node 22 an AsyncLocalStorage is never released once used, and every one is visited whenever an async resource is created, so a process that created many Capsule instances (for example one per request) slowed down in proportion to how many it had ever created. Measured on a bridge worker that builds one Capsule per request: 2000 requests took 5.3 s before and 0.09 s after, and 8000 requests stay flat at about 0.04 ms each.
- f78c06f: Redact credentials following a `Bearer ` prefix under the strict redaction profile, regardless of token format.
- d561f4c: A capture deadline, observation deadline or interval, or HTTP `requestTimeoutMs` of 2^31 ms (about 24.8 days) or more no longer expires after 1 ms. Node fires a longer `setTimeout` after 1 ms; these timers now wait the largest delay Node supports instead.
